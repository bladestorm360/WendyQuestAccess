# Mod implementation and verification

The first active checkpoint covers the title, file selector, retry and native Options. The [feature register](feature-checkpoint.md) tracks the remaining systems and acceptance limits.

## Plugin entry and title lifetime

Blackmoon Prophecy demonstrates last-entry RPG Maker plugins and reapplication after an update. Its native Tolk addon uses a synchronous startup wait and join around a serialized worker. WendyQuest uses the same loader pattern with a separate service and a different lifetime boundary. The applicable runtime is stock NW.js 0.48.4, Node 14.12.0 and modules ABI 83. The official NW.js archive's `nw.dll`, `nw_elf.dll` and `node.dll` match the installed files byte for byte. The generated plugin bundle uses language features supported by that release. The [upstream release](https://nwjs.io/blog/v0.48.4/) and the [exact game build](engine-evidence.md) identify the evidence inputs.

The stock MZ title scene runs while the intro is hidden. `TitleSceneArranger` displays and activates its custom command window only on completion of the final intro coroutine. `MenuScene` provides the Start Game command and its `continue` handler. There is no stock plugin event for this custom activation. The install plan uses one exact-build local notification at byte offset 17749 of `TitleSceneArranger.js` and a last entry in `plugins.js`. The notification runs after native activation. The plugin subscribes once to PIXI 5.3.12 `postrender` and checks stage, window, fade and overlay state before hooking the current window instance. This keeps the feature and its hooks outside startup and avoids a frame poll. [Registration transforms](../tools/registration.py) check both original SHA-256 values and generate candidate bytes in memory. Recovery and atomic application are still part of the deployment milestone.

[Title observation](../src/frontend/title.js) captures only a current selected command's index, bounded name and enabled state. It closes the shared epoch before the accepted native `continue` or `exit` handler, then preserves the original arguments and return. Blur and pagehide retire the epoch. Focus may open a fresh epoch only for the same still-presented, active title. The new scene has its own window and readiness notification. Old instances lose the observer's references at exit. No text-content deduplication is used.

[Registration](../tools/registration.py) also marks the pre-construction entry of `SceneManager.goto` and the accepted Chromium reload branch of `SceneManager.reloadGame`. A pending or active front-end presentation clears its marker and retires its observer before either native operation. A scene without the marker bypasses the mod callback. Explicit window and save-action closures still handle work that begins before `goto`. The installed-method fixture exercises direct scene change before and after first presentation and developer reload after admission, using an inert constructor or reload sink. The [map entry trace](engine-evidence.md#map-entry-ordering-for-the-first-field-checkpoint) identifies the earlier boundaries needed for future field and dialogue observers.

## Speech service

[The renderer](../src/runtime/renderer.js) queues at most eight outstanding records and publishes admission in a single `Int32Array` word. It starts the Node worker in a deferred callback and verifies that the presentation that requested it is still current. NW resolves the service path from the browser context's `process.mainModule.filename`, as the shipped MZ save and launch code does. The renderer never loads a speech DLL. Stale packets are dropped by epoch. Overload currently counts rejected records. The [worker's speech formatter](../src/services/speech-text.cjs) caps the final UTF-16 payload at 256 code units. Backend interruption remains a separate condition from queue cancellation.

[The Node service](../src/services/speech-worker.cjs) launches an absolute, local, hidden helper process from the worker. One bounded request crosses the pipe at a time. [The helper](../src/services/windows/speech.cpp) owns PRISM and selects an output route with braille where supported. It loads the pinned library with application/system directory search, and stops availability polling after selecting a backend. `--check` confirms that the packaged provider opens without speaking.

[The helper protocol](../src/services/windows/speech-pipe.hpp) starts the pipe before initializing PRISM. It asks the worker to compare the queued request's epoch to the live epoch after reading the text and again after first-time provider initialization. The helper discards a refused request and the renderer records it separately from provider completions. This adds one pipe round trip per request and a second round trip on first use. Ordinary native closure retires pending work. Focus requests use the provider's interrupt flag. The initial choice after a dialogue prompt uses the same epoch and an append request.

A grant can be in transit when the gate closes, and an already-entered provider call, initialization or cleanup can outlast the gate. The stalled-provider fixture confirms the game-side close returns independently. That proves native progress while waiting for the provider, and the release gate for provider quiescence remains open. PRISM 0.18.3 exposes separate output and Stop calls without a public in-flight cancellation contract. Win32 I/O cancellation is a request whose result depends on the operation and driver. The interval between grant and provider entry is covered by the approved Wendy Quest transition exception below. [PRISM 0.18.3 interface](https://raw.githubusercontent.com/ethindp/prism/v0.18.3/include/prism.h) · [Windows cancellation contract](https://learn.microsoft.com/en-us/windows/win32/fileio/canceling-pending-i-o-operations).

### Speech master

Open **F8 → Speech** and activate **Speech enabled**. Speech starts on and the setting persists in the NW profile. To restore it, open the same submenu while muted. Use the current settings key, **F8** by default, or enter controller mod mode with **View/Select** and press **Start/Menu** on the default bindings. The renderer waits for the speech preference when profile storage exists. It keeps up to eight records for the currently presented context during the read. Native closure clears the records, and the first output after the read still requires the current presentation. The observer's context token is separate from the output epoch so disabling speech retains live dialogue review and state. Changing the master retires queued work and requires a fresh request for restored speech. While muted, the same current-context records reach only the provider's dedicated braille operation, where available. Once the worker learns that braille is unavailable, the renderer skips muted submissions. [Renderer admission](../src/runtime/renderer.js) · [Worker and capability handshake](../src/services/speech-worker.cjs)

It rechecks the modal's epoch before granting the stop, and closing settings revokes that epoch before native control resumes. The helper uses the capability flag and calls Stop only after it has submitted speech. It reports unsupported or failed Stop without discarding the selected mute setting. Actual stopping time and braille display behavior depend on the user's provider.
