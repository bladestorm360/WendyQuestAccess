# Mod implementation and verification

The first active checkpoint covers the title, file selector, retry and native Options. The [feature register](feature-checkpoint.md) tracks the remaining systems and acceptance limits.

## Plugin entry and title lifetime

Blackmoon Prophecy demonstrates last-entry RPG Maker plugins and reapplication after an update. Its native Tolk addon uses a synchronous startup wait and join around a serialized worker. WendyQuest uses the same loader pattern with a separate service and a different lifetime boundary. The applicable runtime is stock NW.js 0.48.4, Node 14.12.0 and modules ABI 83. The official NW.js archive's `nw.dll`, `nw_elf.dll` and `node.dll` match the installed files byte for byte. The generated plugin bundle uses language features supported by that release. The [upstream release](https://nwjs.io/blog/v0.48.4/) and the [exact game build](engine-evidence.md) identify the evidence inputs.

The stock MZ title scene runs while the intro is hidden. `TitleSceneArranger` displays and activates its custom command window only on completion of the final intro coroutine. `MenuScene` provides the Start Game command and its `continue` handler. There is no stock plugin event for this custom activation. The install plan uses one exact-build local notification at byte offset 17749 of `TitleSceneArranger.js` and a last entry in `plugins.js`. The notification runs after native activation. The plugin subscribes once to PIXI 5.3.12 `postrender` and checks stage, window, fade and overlay state before hooking the current window instance. This keeps the feature and its hooks outside startup and avoids a frame poll. [Registration transforms](../tools/registration.py) check both original SHA-256 values and generate candidate bytes in memory. Recovery and atomic application are still part of the deployment milestone.

[Title observation](../src/frontend/title.js) captures only a current selected command's index, bounded name and enabled state. It closes the shared epoch before the accepted native `continue` or `exit` handler, then preserves the original arguments and return. Blur and pagehide retire the epoch. Focus may open a fresh epoch only for the same still-presented, active title. The new scene has its own window and readiness notification. Old instances lose the observer's references at exit. No text-content deduplication is used.

## Speech service

[The renderer](../src/runtime/renderer.js) queues at most eight outstanding records and publishes admission in a single `Int32Array` word. It starts the Node worker in a deferred callback and verifies that the presentation that requested it is still current. NW resolves the service path from the browser context's `process.mainModule.filename`, as the shipped MZ save and launch code does. The renderer never loads a speech DLL. Stale packets are dropped by epoch. Overload currently counts rejected records. The [worker's speech formatter](../src/services/speech-text.cjs) caps the final UTF-16 payload at 256 code units. Backend interruption remains a separate condition from queue cancellation.

[The Node service](../src/services/speech-worker.cjs) launches an absolute, local, hidden helper process from the worker. Only one bounded pipe command is in flight. Game strings are UTF-8 data with line delimiters removed. [The helper](../src/services/windows/speech.cpp) owns PRISM context/backend calls, stops availability polling, and selects a supported output path with braille when offered by the backend. The helper resolves the pinned library with application/system directory search. `--check` qualifies loading and backend availability without calling speech. Availability, speech delivery and supported Stop behavior remain distinct. A posted external backend call can still overlap native loading if it blocks after admission closed. The strict worker-quiescence gate remains open until the bounded shutdown/admission design is verified for every protected phase.

## Reproduction

- Build with `build.ps1 -PrismArchive <official prism-windows-x64.zip for v0.18.3>`. The entry point uses the machine-wide bounded runner and VS x64 compiler. It stages the plugin, helper and attributed PRISM payload in `.build/payload` for development. It has no Steam side effect. The archive's SHA-256 is pinned in [the builder](../tools/build.py). The upstream header emits a C4309 diagnostic under MSVC v145. The binary builds and resolves the expected PRISM API.
- Run `tools/registration.py` against the installed root under the bounded runner. It verifies the five candidate files with Node syntax checking without writing to the Steam install. The local decode utility in `tools/inspect-plugin.py` identifies byte offsets in the obfuscated source from literal tables and restricted arithmetic.
- Run `tests/title.test.cjs` with Node and the installed root under the bounded runner. It evaluates stock title and accept functions in a mock renderer, confirms no admission before the expected presentation state, and confirms native acceptance proceeds after the shared epoch closes. Custom intro, PIXI state and device input are represented by fixture values.
- Run `tests/nw-smoke.py` under the bounded runner with the official NW archive and installed root. It creates an isolated hidden synthetic app and verifies the generated plugin, actual NW browser-to-Node Worker bridge and distinct shared admission epochs for title and file selector. Installed DLLs are read only for hashes. The worker in this fixture returns a silent receipt. It never loads a game package.
- Run `WendyQuestSpeech.exe --check` under the bounded runner from the payload directory. It returns `R` after opening the packaged PRISM backend. No helper call timing or audible response was measured. Required exact payload security and local deployment checks remain open until the full candidate is ready.
- Run `tests/transport.test.cjs` with Node under the bounded runner. The actual renderer and service code exercised a delayed helper pipe. Verified no worker creation for a retired startup request, one command in flight, an eight-record renderer bound, cancellation without waiting, stale record rejection, repeat speech across a new generation and failed helper handback. The fixture explicitly demonstrates that a cancel command waits for the prior external call to return. It does not establish worker quiescence at native entry.

## File selector, details and deletion

The file selector is custom. `MenuScene` installs a three-column `Window_SavefileList` with native slot indices 0–2 and separate options, studio and conditional reward sprites. Save metadata is already held by `DataManager.savefileInfo`. The selected card displays slot, level, playtime, party portraits and cornerstone icons. Its `loadImages` callback assigns all three atlases and refreshes the list. Until the refresh has reached presentation, the glyphs and card labels are not ready. Record selected card values from the actual draw path and map the distinct sprite-focus states before promising a complete file menu.

The slot's accepted `ok` handler enters `Scene_Load.onSavefileOk`. An empty slot sets up a new game. An occupied slot enters `Scene_FileLoad.create`, which immediately calls `DataManager.loadGame` even though the player has not yet chosen the Load action. Close admission before that accepted native handler. Resume file detail review only when both save read success and the image draw have been published on the current scene. These complete independently in `Scene_FileLoad.onLoadSuccess` and `loadImages`. `executeLoad` may reserve a transfer or reload and runs the native after-load path. Close admission again before the accepted Load action. A failed read returns to the slot list. Delete uses a separate confirmation and can run an animation before returning. Do not read files or call the load routine from the mod.

[File observation](../src/frontend/files.js) waits for the marked native completion, current stage, clear fade and PIXI `postrender`. The local [registration transforms](../tools/registration.py) pin the exact native files. `MenuScene.js` publishes card refresh, artwork, text and deletion status. `SceneManager.onSceneStart` and the last native fade update can release the readiness check when the art or text finished earlier. These native completion sites use fixed scalar markers and bypass the observer before readiness. The renderer reads the current card's level, playtime and visible icon data from the already loaded metadata. On the details screen it uses the portrait asset identity and the two exact stats drawn by `Scene_FileLoad.drawDetailsText`. It copies only small bounded records. The mod never reads a save file. Portrait order comes from the two native drawing paths and the build-pinned atlas mapping.

An index of −1 can be a selected Options, More Games or Coupons sprite. The observer checks after the complete native cursor routine and speaks the selected visible control. Accepted window handlers close admission before changing screens. The exact native Options, Coupons, gamepad Cancel and detail Back branches also close admission. More Games opens the native browser and uses focus retirement. Load failure conveys the game's failure feedback after the replacement file list is presented. The delete confirmation reads the native choices. The running deletion animation can announce its own rendered status once per accepted attempt. Admission closes again before the native delete call. A repeated deletion attempt reuses the same window binding. A stale image or data completion cannot reopen a retired scene.

Run `tests/files.test.cjs` with Node and the installed root under the bounded runner. It uses the original installed file callbacks in memory with the checked local notifications and the production observer. The fixture passed both image/text orders, images arriving before and after stage publication, fade admission, visible slot and sprite focus, exact displayed details, pre-acceptance close, a failed read returning to the slot selector, and the native deletion coroutine using a stand-in store. It substitutes metadata, image objects, clocks and renderer events. It does not establish audible timing or production UI presentation.

## Native Options

`MenuScene` owns `Scene_Options` and `Window_Options`. The window's `ImageLoader` callback assigns the pip and outline artwork, paints the attached window and marks it ready. `drawItem` captures the status string for the current row at the end of its actual draw. `drawVolumeStatus` distinguishes accepted pips from the mouse preview. [Options observation](../src/frontend/options.js) announces the native row or tab, displayed setting value and focused system button. Volume uses the ten rendered thresholds. Zero is muted. A changed setting is a native acceptance event even when the new value lights the same number of pips. The scene's Back, Title and Quit buttons, outside click and accepted window handlers close the existing presentation before passing control to the native action.

An accepted fullscreen change closes the speech epoch and suppresses further speech in that Options instance. A same-value write attempt leaves admission as it was. `MonkeyWrenchMZ._requestFullScreen` retries the NW window action until a terminal condition. `_cancelFullScreen` schedules a later `_resizeNwjsToExactScaleWhenWindowed` callback, which issues the final resize and positioning. The first `Graphics._onWindowResize` can precede that work. A native completion signal for both directions, handling duplicate requests, failed transitions and developer F4, remains open. Follow the native terminal callbacks with a matched NW fixture before resuming Options speech after fullscreen. Real in-game resize and external speech quiescence remain unverified.

## Game-over retry

`MenuScene` adds retry commands to `Scene_Gameover` after the stock command constructor. The frame alpha is zero, and the commands draw into the separate MZ client area. `UIGeneral` loads the button artwork and paints an attached window. A three-bit draw marker records that the selected row and any associated prompt reached the native draw path. Stage, fade and postrender still gate admission. The optional Dave command appears only when the game adds it. Accepted Title, Continue and Dave handlers close the epoch before the native transition or save read. Failed reads preserve the native return to title and add one spoken failure notice on that title's first presented focus.

The bounded Node fixtures use the installed Options draw and volume callbacks, shared artwork callback, retry command creation and acceptance, failed read and title presentation. They check pip counts against recorded drawing calls, a same-pip accepted change, tab changes with the same row index, safe suspension across the first resize, the optional Dave row, and title return without a save read. Fake artwork, storage, window geometry and renderer events isolate game resources. The final generated bundle passed the matched hidden NW worker bridge and syntax checks for all five registration candidates. No gameplay or audible timing was measured.
