# Spatial audio

The shared output service currently plays on-demand previews from the **Audio** group in mod settings. Open settings with **F8** on the default keyboard binding, choose **Audio**, then choose **Preview ahead**, **left**, **right**, **behind** or **above**. The settings dialog also accepts its configured controller navigation and confirm/back actions. **Mod sounds** and **HRTF** are independent and both default on. They persist in the NW profile. Turning sounds off prevents previews and retains the HRTF preference. Returning to the root focuses **Audio** again. The separate speech master and field cues remain open in the [feature register](feature-checkpoint.md).

The preview status reports the output mode selected for the cue. A request that loses its dialog or scene drops its status. The fallback pans left and right relative to the listener and lowers pitch to 72% of the forward pitch across the rear half-plane. HRTF uses the same original cue with a three-dimensional bearing and the built-in OpenAL Soft dataset. The listener's axes are right, up and forward. The bridge reverses the forward axis for OpenAL's default listener orientation. Compare front, behind and above with headphones during final gameplay testing. Native game audio is owned by the game.

## Ownership and cancellation

- [The renderer service](../src/runtime/audio.js) starts a single Node worker on demand after the owning dialog passes its readiness checks. One request may be in flight and one newer request may wait. Each request sends a generation, three bearing components, a gain and the HRTF selection. Scene objects and readiness predicates stay on the renderer. Replacing a preview revokes its predecessor. A worker error closes admission and reports the output failure to the current dialog.
- [The plugin](../src/plugin.js) admits previews only for the focused, presented Audio dialog in the current scene. Group exit, sound/HRTF changes, settings retirement, native scene departure, resize, blur and page hide revoke admission before replacement work. The renderer only stores the closed generation. It never joins the worker or waits for the audio device.
- [The Windows addon](../src/services/windows/audio-addon.cpp) binds the narrow Node-API exports in the loaded NW `node.dll` and owns the SDK objects on the Node worker. It keeps a strong Buffer reference to the shared 32-bit admission word until the SDL stream has been destroyed. SDK entry points use application-relative absolute paths and constrained DLL lookup. The service declines a preloaded SDL3 or OpenAL Soft module of the same name. The DLLs remain separate from the addon. [Node 14 Node-API](https://nodejs.org/download/release/v14.12.0/docs/api/n-api.html#n_api_napi_get_buffer_info)
- [OpenAL Soft loopback](../src/services/windows/audio-hrtf.hpp) renders 48 kHz stereo into a bounded array on the worker, checking admission between 128-frame slices. It requires the runtime to report HRTF enabled and select its exact built-in dataset. The original [preview cue](../src/services/windows/spatial-cue.hpp) is generated from a 90 ms tone with a harmonic and a short envelope. If HRTF is off or unavailable, the worker renders stereo and rear pitch with the same cue definition.
- [The SDL stream](../src/services/windows/audio-device.hpp) is the one hardware output for this service. The callback checks the shared generation and copies at most 1,024 source frames in subchunks of at most 256, checking again before each submission. It does no geometry, synthesis, speech or file I/O. SDL provides the stream lock and controls callback lifetime. The worker publishes completed PCM and owns stream destruction. [SDL callback locking](https://wiki.libsdl.org/SDL3/SDL_AudioStreamCallback) · [SDL stream lifetime](https://wiki.libsdl.org/SDL3/SDL_OpenAudioDeviceStream)

## Offline evidence

November 11, 2026, Steam build 26578620. The bounded 512 MB build with `-VerifyAudio` passed the native fixture with the shipped SDL3 3.4.4 and OpenAL Soft 1.25.2 x64 libraries. It checked left/right channel energy, different front/rear/above HRTF outputs, rear pitch across the full rear half-plane and the callback's sample submission after replacement and revocation. The native fixture opened loopback in about 285–310 ms and rendered five warm cues in about 10–12 ms under the runner's 8.33% CPU cap. The isolated NW test used the matching 0.48.4 runtime and Node 14.12.0, a synthetic window, the production addon and the silent SDL driver. It verified HRTF preview, explicit stereo preview, the sounds-off switch, dialog focus and both saved settings after restart. Cold HRTF status appeared after about 505 ms with 40 ms polling. The [renderer fixture](../tests/audio.test.cjs) verifies early revocation, queue replacement, stale receipts and worker loss.

These measurements end at generated PCM, silent submission or UI status. Actual audible onset, hardware buffering, direction recognition, coexistence with native audio and comparable native application overhead remain unverified. The shared generation prevents new callback submissions after the callback observes closure. An SDK call already entered, PCM already buffered in SDL or the device, and idle SDL callback checks can span a phase change. Verify or remove that overlap before accepting phase quiescence. The cold preview figures also leave live cave timing open. Before attaching live cues, qualify safe arming, readiness, warm end-to-end latency against the actual crossing window, and prompt cancellation under load. Wall feedback, beacon, soundscape, cave alerts and category controls still need their native producers and fixtures.

## Dependencies and payload check

The builder uses the approved FFPR SDK inputs by default and accepts `-AudioSdkRoot` for an equivalent local source. It verifies the key input hashes before staging the two runtime libraries and their notices in `audio-deps`. OpenAL Soft includes its MIT KEMAR measurements in the DLL. The matching corresponding-source URL and measurement attribution travel in `audio-deps/SOURCE.txt`. The Windows release must preserve those files and the SDL license. The current platform target is Windows x64. [SDL 3.4.4](https://github.com/libsdl-org/SDL/releases/tag/release-3.4.4) · [OpenAL Soft 1.25.2 HRTF](https://github.com/kcat/openal-soft/blob/1.25.2/docs/hrtf.txt) · [MIT KEMAR measurements and terms](https://sound.media.mit.edu/resources/KEMAR.html)

Static PE inspection confirmed x64 for the addon and both audio SDKs. The addon exports `napi_register_module_v1` and imports `KERNEL32.dll`. The SDKs' static imports are Windows system libraries. Microsoft Defender custom-scanned the extracted development payload on November 12, 2026 at about 06:12 UTC and reported no threats. Platform 4.18.26100.4, engine 1.1.26100.4, definitions 1.463.257.0 updated at 05:18 UTC. The native files reported `NotSigned`. The final release still needs its own exact payload and installer checks, signing status and installed verification.
