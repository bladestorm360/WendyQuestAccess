# Pause and inventory menu access

The pause menu speaks the active command after the native menu is rendered. Inventory speaks the active category or item, its displayed quantity, availability or equipped marker where applicable. Press **I** for the current item's description and displayed equipment comparison. **Shift+Up** and **Shift+Down** move between detail lines. **Shift+Left** and **Shift+Right** jump to the first and last line. Ordinary arrows still navigate the game menu.

On a controller, press and release **View/Select**, then **A** on an Xbox layout to read details. In mod mode, the D-pad directions review the same lines or jump to the first and last line. Each review action returns the controller to ordinary menu input. The effective bindings are listed and can be changed under **Keyboard bindings** or **Controller bindings**. Under **Speech**, **Autodetail** appends the current details after focus, and **Menu indexing** adds position and count to focus and review. Both default off and persist independently. ## Manual Save feedback

Select **Save** in the pause menu. Speech waits for the native write and the return of menu control. The mod reads the completed banner, including the game's changing messages on repeated saves. While **Save** is selected, press **I** or the controller details action to review the latest feedback. The existing review controls move through multiline text. A rejected write produces the mod's **Could not save the game** status. The game uses the same manual banner even when the write is rejected.

`Scene_Menu.commandSave` at byte 9348 of `MenuScene.js` starts the existing storage request and native banner coroutine. The banner attaches at 11992. `Scene_Base.executeAutosave` at 65235 of `MonkeyWrenchMZ.js` reports native write completion through its promise. The markers track the current manual request through completion. The shared menu observer verifies the actual letters in the presented banner after the native save gate opens. If a slow write outlasts that banner, the native success popup at 66555 provides the painted feedback. The copied result joins the menu focus when the native command returns. The mod keeps only the latest result in the current pause menu.

## Shop browse

The buy list speaks the selected item, its displayed price and whether the game currently enables it. **I** or the controller details action reads the visible description, owned count, gold balance and equipment comparison. Autodetail and menu indexing use the same independent settings as Inventory. Native arrows, confirmation and cancellation retain their usual actions.

The installed build opens the buy list directly. The final `Scene_Shop.create` override at byte 59714 of `MenuScene.js` calls the native Buy command. The scene update observes the active window after `Scene_MenuBase.update` at byte 33497 of `rmmz_scenes.js`. The stock `Window_ShopBuy.drawItem` at 97671 of `rmmz_windows.js` supplies the actual row, price and paint-opacity decision. The markers pair each row with its active item list and bitmap.

The help, balance and possession come from the completed paint at `MenuScene.js` bytes 62841, 16629 and 64004. The native possession count includes an equipped copy when the shop displays one. The stock equipment pane uses the drawn actor, current equipment and displayed attack or defense difference. A stale paint or hidden pane is withheld. Native `Scene_Shop.onBuyOk` at 61172 retires browsing before opening the quantity window.
