One target coordinate is outside its destination map, at Map 185 event 18 page 0 command 6. Sixteen commands target their own map.

The strict first slice is a direct transfer as the sole executable command on an unconditional, single-page event, from one map to another with an in-bounds landing. Common events precede another 220 direct commands on ordinary interaction pages. These shapes need separate qualification before the planner can use them.

Group by source and destination for directed pairs and by native priority for approach classes. This scan uses installed data in memory and records counts and locators only.

## Directions to a bookmark on a neighboring map

While walking, choose a bookmark in the pathfinder's **Bookmarks** category and use Directions. The mod gives the route to a reachable entrance. Step onto a floor entrance yourself when the route tells you to move, or face the announced direction and press the game's action button for a solid entrance. After the map settles, use Directions again to find the bookmark from the landing. The mod reports when it cannot find a reachable entrance, including when another native event blocks the approach. [Bookmark controls](bookmarks.md#find-a-bookmark)

[The entrance owner](../src/world/transfer-bookmarks.js) resolves the live source page and uses the local event ID, page, coordinates and priority. The [route worker](../src/world/route-worker.cjs) bounds the transfer landing using dimensions added by the [local geometry bake](../tools/bake-world.cjs). Rebuild older geometry manifests to enable these directions. The [solver](../src/world/routes.cjs) chooses a reachable approach using one outward traversal. It honors native touch-event order and Action Button priority. The request reads current-map geometry. The already-loaded manifest supplies the destination dimensions. The installed shape check matched all 463 candidate pages, with at most 28 entrances to one map in a request. Every request still checks current events, blockers and the intervening floor triggers.

The [registration adapter](../tools/registration.py) observes the selected native event immediately before interpreter setup, then verifies the actual reservation before the original transfer starts. The reservation must come from the expected main interpreter list and event ID and match the target map and tile. The [field owner](../src/world/field.js) drops route work and output on native leave. It keeps the bookmark identity and exact landing through loading. Once the new scene reaches settled postrender readiness, the owner matches the same native map and player objects, expected map and tile, and current bookmark revision. It selects the bookmark for a fresh command. Selection does not start movement or audio.

The [installed-method fixture](../tests/transfer-bookmarks.cjs) checked normal priority on 019 → 020 and below-player priority on 017 → 113, actual event acceptance and reservation, multiple eligible entrances, a changed entrance, a wrong landing and an out-of-bounds destination. It also checked the conditional house stair exclusion and synthetic interruption by a different floor event. The [matching NW.js fixture](../tests/nw-smoke.py) used the packaged worker and the installed acceptance and reservation methods in a synthetic scene. It checked settings selection, entrance speech, the last step reserved for native input, rejection during load and the restored bookmark selection.

Under the CPU cap, valid packaged route round trips were 40.5–45.3 ms cold and 0.5–1.9 ms warm. In the synthetic NW fixture, input through submission took 0.7–0.8 ms, the silent speech receipt was observed after 25.3–25.5 ms with 40 ms polling, and settled handback took 0.1 ms. The ordinary warm field command in those runs took 0.6–0.9 ms through submission. Physical audio timing and combined cost during live movement, event entry and loading remain open.

## Routes across several walking maps

Use the same **Bookmarks** category for a farther walking destination. **Next entrance toward** means there is another transfer after this one. Request directions again after each map settles. When the route reaches the saved map, the next request resolves the exact tile or the current linked entity. Enter each transfer with the native controls. If another event takes control or a different transfer is reserved, select the bookmark again.

The local bake compiled 549 qualified transfer options on 95 maps into 179 exact landing tiles and 285 landing-to-exit links. The 65,803-byte walking catalog is hashed within the existing manifest. The [catalog compiler](../tools/transfer-catalog.cjs) uses authored terrain, possible page collision and floor events to check each arrival tile against its available exits. It also records the tiles reachable from that arrival. The [worker lookup](../src/world/walking-catalog.cjs) ranks available links toward the bookmark by transfers remaining. It uses the destination tile for point bookmarks, so two arrivals on disconnected parts of the same map are distinct. A linked entity is resolved in the loaded map. The live solver checks the next entrance against current terrain, native event priority and blockers before giving directions. A farther connection can change before arrival. Each handback retains the selected bookmark and prior landing tiles, which prevents repeated landings in a route.

The two house stair branches use the same [native branch recognizer](../src/world/transfer-events.cjs) as their ordinary Exits labels. Switches 503 and 525 choose the ordinary or hidden floor. The recognizer checks the branch shape, the direct landing, and the native stair audio common event. The planned route uses the current state and verifies it again before speaking. Native acceptance and reservation must still agree. Timed cave traversal continues through its separate guide. Wider vehicle transfers remain open.

The matching NW fixture requests directions after each of two native reservations and checks that no route resumes during either load.
