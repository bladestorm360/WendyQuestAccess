# Field routing and collision

## Local geometry and worker

The [local bake tool](../tools/bake-world.cjs) reads the installed Steam build 26578620 under the bounded runner. It emits one byte of collision, interaction and landing flags per cell, plus dimensions and map identity. It builds all 239 installed maps and 191,235 cells, including maps whose normal gameplay reachability remains open. The manifest hashes the input and output. Derived files stay outside Git and the development payload. The installer generates these files locally and places them in `package.nw/wendyquest-access-geometry`. The route worker reads that directory. [Local installation](deployment.md) The WQG2 format carries airship landing data. The worker can still read WQG1 geometry for walking and sailing.

[The route worker](../src/world/route-worker.cjs) verifies the geometry build and per-map hash, retains one current map, and accepts copied terrain changes, event occupancy and vehicle state. [Collision composition](../src/world/geometry.cjs) uses a maximum of 16,384 cells, 512 events and two surface-vehicle obstacles. It keeps rectangular blockers to four updates each plus one grid pass. [Route search](../src/world/routes.cjs) finds cardinal routes to eligible walking, boarding and sailing approaches. It returns ordered travel legs, distance in tiles and any required final facing. Cancellation checks during geometry assembly and search discard retired results.

## Destination controls in the development build

On the field, **J/L** move between destinations, **Shift+J/L** change category, **K** reads the selection and **P** requests directions. During an ordinary step, a request can wait for the landing tile to settle. In **Navigation**, switch to **Brackets and backslash** to use **[ / ]** for destinations, **Shift+[ / Shift+]** for categories, **P** to read the selection and **Backslash** for directions. Each layout saves its own remaps and the selected layout persists. Both share the current category and destination. Activate a binding to change it, use Delete to unassign and Escape to cancel. A native binding takes precedence if the game claims the key later. An earlier settings remap that collides with the active navigation layout retains front-end access and uses F8 for recovery on the field.

On a controller, move the **right stick left/right** for destinations and **up/down** for categories. **Left trigger** requests directions. Press **View/Select**, release, then press the south button to read the selected destination or **Menu/Start** to open settings. F8 or its keyboard remap can also open settings in the field. The D-pad and left stick retain native movement. Controller support off restores native controls, with the existing recovery chord available on a settled field. The **Controller bindings** group supports remapping the field controls, including right-stick directions. **Unassign a controller binding** lists the optional bindings that can be cleared. A native controller remap that later occupies a direct field input takes precedence. Legacy settings retain valid mode and recovery bindings, so a preexisting trigger assignment can move the default directions input to the other free trigger or leave it unassigned if both are taken.

[The destination browser](../src/world/destinations.js) selects the nearest destination whenever a category is entered. It uses active native action, transfer, shop and battle pages with authored names or sprite roles for Objects, NPC, Merchants, Exits, Treasure and Enemies. Destination names and cardinal offsets describe the current selection. Each category entry ranks its current destinations by wrapped Manhattan tile distance, using native event order for ties. Its order and selected identity stay fixed during walking, Directions and within-category cycling. Re-entering replaces the previous selection with the new nearest item. Removed IDs disappear; newly available IDs append until the next category entry. Only destination IDs are retained in the existing map/mode-owned browser, with no saved preference, native references, new hooks or worker queries. On the opening beach, **NPC** includes Elder Tater while the follow objective is active. From Objects, **Shift+J** moves to All when using the default layout. Recognized treasure is labeled by type, and ordinary reward-granting pages use a generic interaction label. Directions begin with the route instructions. The read-selection command gives the destination name. Spoken routes give up to eight legs in the form “1 north, 3 east, 4 north,” followed by the final facing or a notice that more directions are available. Accepted native cardinal movement advances one grid cell and calls the native step counter once. Direction speech uses that movement unit. The optional beacon follows the full verified course. Past the bounded warning-sign approach, cave directions offer a short timed preview or an optional one-tile cue. [Route beacon and controls](beacon.md) · [Timed cave directions](puzzles-and-secrets.md#timed-crossing-previews)

**Enemies** uses the name of the field sprite, such as Conehead or Blandhawk. All 206 authored field encounter pages have a verified name. The Lost Ruins Heat Lamp belongs here while it is active. The renderer takes a settled world snapshot at postrender and sends the route worker the candidate event IDs and applicable boarding, landing, entry and waypoint fields. ## Native movement and interactions

Walking follows stock `Game_Map.checkPassage`, `allTiles`, `isPassable` and `Game_CharacterBase.isMapPassable` in `package.nw/js/rmmz_objects.js`. Star layers yield to the next layer. The destination must also allow passage from the reverse direction. Active tile events precede the base layers in the native list order. Normal-priority events and present non-through boats and ships can occupy the destination.

`MapScene.js` `Game_CharacterBase.canPass` at original byte 107092 adds inclusive rectangular blockers. Their priority can differ from their collision state. The current event position and the rectangle offsets determine coverage. Erased and through events yield. The same custom plugin supplies `Game_Player.startMapEvent`, `canTriggerEvent` and `findEventsAt`, starting at byte 109478. The route endpoint tests native action priority and trigger, and supports the stock counter look-ahead only when the nearer tile has no startable event. Boat and ship movement use destination regions via `MapScene.js` `IsWater` at byte 11791. Region 253 is small-boat-only for vessel movement and 254 permits both surface craft. The story boat uses the ship slot. Walking passability comes from the tile layers.

`Tyruswoo_TileControl.js` `Scene_Map.onMapLoaded` at original byte 13959 applies the saved per-map table to the map data before calling native map setup. `setExactTileId` at byte 31297 writes the flattened layer index to that table and updates the live map when editing locally. Autotiling can write neighboring cells through the same setter. The source-checked local write at byte 31935 retires a pending route. `MapScene.js` `TileEditor.FloodFillRegion` at byte 32381 writes successive regions through that setter and yields between rings. The checked generator markers keep the field closed from native scheduling through generator completion. An in-flight route also retires before event page replacement, character and vehicle collision changes, tileset changes and accepted movement. Patrol timing remains a separate producer.

## Native input boundary for autowalk

Press **Ctrl+Backslash** in either keyboard layout to toggle **Autowalk**, or change it in **F8 → Navigation**. The shortcut says “Autowalk on” or “Autowalk off” and saves the same preference. Turning it off cancels owned movement and any pending automatic directions, including between tiles. Then use the ordinary directions key or controller directions control to start a walk when enabled. The binding is remappable under Navigation and appears in Help. Ctrl+Shift+Backslash is also accepted for a custom binding. “Walking” confirms the start of movement and “Arrived” confirms the verified approach or destination. If you are already at the approach, you hear “Arrived.” **Speak autowalk path** is an independent opt-in. It defaults off, and the beacon's full-path setting applies to ordinary directions. Use the native controls to take any final step onto a floor trigger, board, land or activate an object. In the timed cave rooms, Directions still gives the manual approach or crossing cue.

The shortcut uses the same asynchronous preference save as the Navigation menu. Its held-key guard allows one toggle per physical press. Keyboard admission remains limited to the focused, ready field and permits an unsettled step. Turning the preference off revokes the pending directions job and automatic continuation before reporting the new setting. A failed save restores the preceding preference without restarting movement. The native input and matching NW fixtures cover both layouts, repeated input, mid-step cancellation, menu consistency and persistence after restart.

Press **Shift+V** to stop current navigation. On a controller, press and release **View/Select**, then move the **right stick left**. Both bindings are remappable. A native direction or valid pointer destination takes control at the next movement decision. A stop during a native step leaves that step to settle. Moving NPCs or enemies can make Autowalk recalculate silently from the current tile and continue to the same destination. Manual movement, Stop and native loading or event entry still cancel the owned walk.

The installed stock `Game_Player.moveByInput` starts at original byte 222354 in `rmmz_objects.js`. The enabled plugin scan found no override of this method, `getInputDirection` or `executeMove`. Native cardinal input is selected at byte 222457 and a valid pointer destination uses the native path at 222731. The autowalk marker at 222789 runs after those sources are resolved. It supplies a single direction to the ordinary native dispatch at 222822 when both sources yield. The native result marker at 222850 advances the course only when the actual player arrives at the expected logical tile. In MapScene.js, the activity branch at original byte 67386 also recognizes the current Autowalk owner while moving or waiting. It follows the native input activity branch so the game resets its own inactivity timer. The renderer checks the focused, ready scene before admitting this activity, including during interpolation. Stopping, arriving or entering a native event releases that ownership. Dashing, interpolation, collision and follower movement remain in the native methods.

[The autowalk owner](../src/world/autowalk.js) verifies the scene, mode, target, active page, expected position and next native collision edge. On walking and sailing courses it checks the next tile for startable native floor events before dispatch. A planned touch destination ends at the adjacent tile with the activation direction.
