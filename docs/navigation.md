# Field routing and collision

## Local geometry and worker

The [local bake tool](../tools/bake-world.cjs) reads the installed Steam build 26578620 under the bounded runner. It emits one byte of collision, interaction and landing flags per cell, plus dimensions and map identity. It builds all 239 installed maps and 191,235 cells, including maps whose normal gameplay reachability remains open. The manifest hashes the input and output. Derived files stay outside Git and the development payload. The installer will need to generate them in `wendyquest-access-geometry` under the verified NW profile data path. The WQG2 format carries airship landing data. The worker can still read WQG1 geometry for walking and sailing.

[The route worker](../src/world/route-worker.cjs) verifies the geometry build and per-map hash, retains one current map, and accepts copied terrain changes, event occupancy and vehicle state. [Collision composition](../src/world/geometry.cjs) uses a maximum of 16,384 cells, 512 events and two surface-vehicle obstacles. It keeps rectangular blockers to four updates each plus one grid pass. [Route search](../src/world/routes.cjs) finds cardinal routes to eligible walking, boarding and sailing approaches. It returns ordered travel legs, distance in tiles and any required final facing. Cancellation checks during geometry assembly and search discard retired results.

## Destination controls in the development build

On a settled walking map or aboard a settled vehicle, **J/L** move between destinations, **Shift+J/L** change category, **K** reads the selection and **P** requests directions. In **Navigation**, switch to **Brackets and backslash** to use **[ / ]** for destinations, **Shift+[ / Shift+]** for categories, **P** to read the selection and **Backslash** for directions. Each layout saves its own remaps and the selected layout persists. Both share the current category and destination. Activate a binding to change it, use Delete to unassign and Escape to cancel. A native binding takes precedence if the game claims the key later. An earlier settings remap that collides with the active navigation layout retains front-end access and uses F8 for recovery on the field.

On a controller, move the **right stick left/right** for destinations and **up/down** for categories. **Left trigger** requests directions. Press **View/Select**, release, then press the south button to read the selected destination or **Menu/Start** to open settings. F8 or its keyboard remap can also open settings in the field. The D-pad and left stick retain native movement. Controller support off restores native controls, with the existing recovery chord available on a settled field. The **Controller bindings** group supports remapping the field controls, including right-stick directions. **Unassign a controller binding** lists the optional bindings that can be cleared. A native controller remap that later occupies a direct field input takes precedence. Legacy settings retain valid mode and recovery bindings, so a preexisting trigger assignment can move the default directions input to the other free trigger or leave it unassigned if both are taken.

[The destination browser](../src/world/destinations.js) remembers one selection per nonempty category. It uses active native action, transfer, shop and battle pages with authored names or sprite roles for Objects, People, Merchants, Exits, Treasure and Enemies. Destination names and cardinal offsets describe the current selection. A new category without a prior selection starts at its nearest grid offset. Recognized treasure is labeled by type, and ordinary reward-granting pages use a generic interaction label. Spoken routes give up to eight legs in the form “1 north, 3 east, 4 north,” followed by the final facing or a notice that more directions are available. Accepted native cardinal movement advances one grid cell and calls the native step counter once. Direction speech uses that movement unit. The optional beacon follows the full verified course. Past the bounded warning-sign approach, cave directions offer a short timed preview or an optional one-tile cue. [Route beacon and controls](beacon.md) · [Timed cave directions](puzzles-and-secrets.md#timed-crossing-previews)

[The field owner](../src/world/field.js) accepts a command after native restoration, fade, movement, idle, save, terrain and display readiness, then rechecks on the rendered frame. [The snapshot](../src/world/snapshot.js) reads the active event positions and pages, the authoritative tile-event list, present boats and ships, and changed terrain cells from the already-restored tile table. Terrain moves as a compact transferable buffer. The renderer allows one worker request in flight, with one replacement request. Native movement, collision changes, flood entry, resize and transitions revoke the active request and any pending output. A result needs the same live owner, map and request identity. The development route makes no native movement or interaction call.

## Native movement and interactions

Walking follows stock `Game_Map.checkPassage`, `allTiles`, `isPassable` and `Game_CharacterBase.isMapPassable` in `package.nw/js/rmmz_objects.js`. Star layers yield to the next layer. The destination must also allow passage from the reverse direction. Active tile events precede the base layers in the native list order. Normal-priority events and present non-through boats and ships can occupy the destination.

`MapScene.js` `Game_CharacterBase.canPass` at original byte 107092 adds inclusive rectangular blockers. Their priority can differ from their collision state. The current event position and the rectangle offsets determine coverage. Erased and through events yield. The same custom plugin supplies `Game_Player.startMapEvent`, `canTriggerEvent` and `findEventsAt`, starting at byte 109478. The route endpoint tests native action priority and trigger, and supports the stock counter look-ahead only when the nearer tile has no startable event. Boat and ship movement use destination regions via `MapScene.js` `IsWater` at byte 11791. Region 253 is small-boat-only for vessel movement and 254 permits both surface craft. The story boat uses the ship slot. Walking passability comes from the tile layers.

`Tyruswoo_TileControl.js` `Scene_Map.onMapLoaded` at original byte 13959 applies the saved per-map table to the map data before calling native map setup. `setExactTileId` at byte 31297 writes the flattened layer index to that table and updates the live map when editing locally. Autotiling can write neighboring cells through the same setter. The source-checked local write at byte 31935 retires a pending route. `MapScene.js` `TileEditor.FloodFillRegion` at byte 32381 writes successive regions through that setter and yields between rings. The checked generator markers keep the field closed from native scheduling through generator completion. An in-flight route also retires before event page replacement, character and vehicle collision changes, tileset changes and accepted movement. Patrol timing remains a separate producer.

The cave adapter recognizes the island's conditional entrance, the internal floor transfers and the chamber return in **Exits**. Active floor mechanisms and the chamber statue appear in **Objects**. The worker uses the same live collision and native-priority approach for all of them, including the adjacent touch approach to the return exit. Native entry prompts and event handback govern the cave progression. [Cave progression and chamber](puzzles-and-secrets.md#cave-progression-and-chamber)

### Gated exits and floor events

In **Exits**, the two house stairs read their ordinary floor until the matching native passage opens. They then read **Secret room stairs**. **Objects** lists the hidden passage buttons. Caffeine Caverns has a **Hidden cave entrance** with a first-visit touch approach and a subsequent action-button page. From inside, choose **Return to Caffeine Caverns**. The Cauldron lists current entrances and returns in **Exits** and active pull handles in **Objects**. French Fry Forest lists the gate switches in **Objects**. [Authored access states](puzzles-and-secrets.md#ordinary-progression-and-secret-reachability)

When directions say “Floor event one tile north,” the described route stops on the tile before the event. Native controls still let you approach it and continue through any dialogue or scene. Request directions again when control returns. A guard may turn you back. If you are already standing on the selected touch entrance and can leave and return safely, directions ask you to walk off the tile and back. The beacon follows complete routes to the selected interaction.

[The local labels](../src/world/local-destinations.js) use the settled map and active event pages. The stair labels validate the two stock condition/transfer branches and read the corresponding live switch. The installed switch writes occur on the other side of the stairs or in the secret room, and the existing native map transition retires the old route. The registration verifier fingerprints the maps with these locators. Map 087 has a specific 1,463,068-byte read ceiling matching the installed file.

Stock `Game_Player.updateNonmoving` runs the on-tile touch check after a native step before continuing player input. The custom event check recognizes event rectangles and ignores the through flag for activation. `Game_Map.setupStartingMapEvent` accepts the first eligible starting event in map order. The worker builds a bounded tile table from the copied active non-normal touch events. It searches for a route clear of incidental events first. If only a geometrically walkable path exists, a second search traces its prefix to the tile before the first event. A selected touch entrance may still be the final tile. This uses the existing native markers and route worker. Moving actors, actions at a distance and special timed traversal have their own readiness and collision rules.

### Native vehicle transitions

Use **Vehicles** to select a parked **Boat** or **Board the boat from the island dock**. A parked boat route tells you which way to face before pressing the game's action button. The island dock route includes the final step that activates the native boarding event. On the boat, use **Exits** for **Float Fort**, **Breaded Bay** or **Secret Island boat landing**. After the island landing scene settles, request walking directions to **Secret Island**. At the named discovery event, use the native controls to cross the indicated tile. Request directions again after it settles. The island and Lost Ruins return exits appear as **Return to world map**. [Navigation controls](#destination-controls-in-the-development-build)

The authored world boat is the engine's ship slot. Common Event 139 relocates it on Map 113 to one of three story docks and uses stock interpreter commands 202 and 206 to place and board it. The airborne vehicle uses the engine's airship slot. `System.json` gives all three vehicle slots map ID zero initially. The boat and airship need live position and ownership evidence before they can become route targets.

The installed `Tyruswoo_TileControl.js` override of `Game_Player.triggerButtonAction` attempts native boarding or landing while outside the surface vehicles. It skips the on/off call while driving the boat or ship. The authored surface exits call `Game_Player.getOnOffVehicle` through event command 206. Normal travel should guide the player to these authored events. Stock `getOnVehicle` checks the current tile for an airship and the facing tile for ship and boat, in that order. Stock `getOffVehicle` checks `Game_Vehicle.isLandOk`, then changes follower, vehicle, movement and transparency state. The native getting-on and getting-off updates finish that handback after the corresponding native conditions.

### Airship landing trace

On foot, choose **Airship** in **Vehicles**, follow directions onto its tile, and press the native action button. Wait for the ascent to finish. In flight, choose **Nearest landing site** in **Vehicles**, or choose an **Exits** destination to find a landing with a connected walking approach. Follow the flight directions and press the action button to land. If directions name a discovery event, select that event in **Objects** after landing, then request directions to the entrance again once the discovery completes.

Stock `Game_Vehicle.updateAirshipAltitude` changes the altitude by one per native update between 0 and 48. `canMove` waits for `isHighest`. Stock `Game_Player.updateVehicleGetOn` enables through after followers and movement settle. An accepted landing starts descent and clears through. `updateVehicleGetOff` restores walking control after `isLowest`. The field gate admits flight only for the current native Map 113 aircraft at cruising altitude with its driving and through flags. Existing boarding and landing markers retire the old directions, beacon and input ownership before native handback. [Vehicle owner](../src/world/vehicle-navigation.js)

For landing, `MapScene.js` `Game_Map.isAirshipLandOk` tests valid dry regions and stock `checkPassage` with masks 0x800 and 0x0f. A partial direction mask can defer to the next lower layer. Stock `Game_Vehicle.isLandOk` also checks `eventsXy`, including inactive and erased events still held in the native map list. The bake and changed-tile snapshot preserve the mask result. The worker removes live occupied landing tiles. Before speech, the renderer calls the actual native landing predicate once at the proposed tile. The beacon checks it again at arrival. [Geometry](../src/world/geometry.cjs) · [Route search](../src/world/routes.cjs) · [Beacon](beacon.md)

For a selected exit, the worker searches native walking edges backward from its eligible approach, excluding intervening touch events. It chooses a connected landing using combined flying and walking tile counts. When only the paired discovery is reachable, it can route to a landing with a safe walking approach to that discovery. The paired events come from the installed marker writes at the actual entrance coordinates. The first attempt still needs the native discovery and a new route after the resulting page and terrain changes. [Discovery register](puzzles-and-secrets.md#ordinary-progression-and-secret-reachability)

The [installed-method fixture](../tests/vehicle-navigation.cjs) compared **9,504** landing results across all 2,376 world-map tiles in four states. It covered 636 available tiles in the base state, an erased actor moved onto and away from a valid tile, and a restored region change that removed one landing. The fixture boarded the parked aircraft, checked all 48 native updates in ascent and descent, rejected native landing over water, verified a beacon recheck against new occupancy, and followed the actual Lost Ruins 17 discovery and terrain write after landing. Graphics, audio and interpolation used stand-ins. The matching Map 113 worker measured 44.8–47.6 ms cold and 0.8–1.0 ms warm in the later bounded runs. The [field fixture](../tests/field.test.cjs) used the normal directions key, checked cruise admission and rejected a site invalidated before speech. A throttled dense walking snapshot with 9,600 changed cells took 3.3–4.4 ms. Actual frame delay and audible response remain gameplay checks.

## Native input boundary for autowalk

Turn on **Autowalk** in **F8 → Navigation**, then use the ordinary directions key or controller directions control. **Speak autowalk path** is independent and also defaults off. Arrival and blocked-route feedback are available in either narration state. Autowalk follows eligible walking, sailing and flight routes. In the timed cave rooms the directions control continues to provide the manual approach or crossing cue. Use the native controls to take the last step onto a floor trigger, board, land or activate an object.

Press **Shift+V** to stop current navigation. On a controller, press and release **View/Select**, then move the **right stick left**. Both bindings are remappable. A native direction or valid pointer destination takes control at the next movement decision. A stop during a native step leaves that step to settle. If the route changes, request directions again from the current tile.

The installed stock `Game_Player.moveByInput` starts at original byte 222354 in `rmmz_objects.js`. The enabled plugin scan found no override of this method, `getInputDirection` or `executeMove`. Native cardinal input is selected at byte 222457 and a valid pointer destination uses the native path at 222731. The autowalk marker at 222789 runs after those sources are resolved. It supplies a single direction to the ordinary native dispatch at 222822 when both sources yield. The native result marker at 222850 advances the course only when the actual player arrives at the expected logical tile. Dashing, interpolation, collision and follower movement remain in the native methods.

[The autowalk owner](../src/world/autowalk.js) verifies the scene, mode, target, active page, expected position and next native collision edge. On walking and sailing courses it checks the next tile for startable native floor events before dispatch. A planned touch destination ends at the adjacent tile with the activation direction. A new floor event or blocked edge stops the route. A live route change retires its speech and marks the course ineligible for further dispatch. Native event, menu, vehicle and scene boundaries clear ownership. The worker encodes the whole course before limiting narrated legs. If a route ends at an interaction, narration describes the automatic portion and gives the remaining manual direction. It shares the existing bounded route worker and does no native action-button input. [Route worker](../src/world/route-worker.cjs)

The [installed-method fixture](../tests/autowalk.cjs) followed native routes on foot, on the boat and in flight. It checked default-off, native manual direction priority, a valid zero-movement pointer destination, changed collision, an intervening floor event, transfer retirement, manual door activation, dock stop and landing handback. The matched NW fixture verified the ordinary directions key, both narration settings, spoken arrival, cancellation during an unsettled step and preference persistence on restart. With interpolation and output stand-ins, the serial bounded run measured **48 matched steps** at 1.95 ms manual and 3.20 ms autowalk in total. The Map 197 worker returned the course in 44.3 ms cold and 0.9 ms warm in that run. In-game frame delay, input feel and audible latency remain gameplay checks.
