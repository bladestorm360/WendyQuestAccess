# Field routing and collision

## Local geometry and worker

The [local bake tool](../tools/bake-world.cjs) reads the installed Steam build 26578620 under the bounded runner. It emits one byte of collision and interaction flags per cell, plus dimensions and map identity. It builds all 239 installed maps and 191,235 cells, including maps whose normal gameplay reachability remains open. The manifest hashes the input and output. Derived files stay outside Git and the development payload. The installer will need to generate them in `wendyquest-access-geometry` under the verified NW profile data path.

[The route worker](../src/world/route-worker.cjs) verifies the geometry build and per-map hash, retains one current map, and accepts copied terrain changes, event occupancy and vehicle state. [Collision composition](../src/world/geometry.cjs) uses a maximum of 16,384 cells, 512 events and two vehicle obstacles. It keeps rectangular blockers to four updates each plus one grid pass. [Route search](../src/world/routes.cjs) finds a shortest cardinal route to a tile or an eligible on-foot event approach. It returns ordered travel legs, distance in tiles and any required final facing. Cancellation checks during geometry assembly and search discard retired results.

## Destination controls in the development build

On a settled walking map, **J/L** move between destinations, **Shift+J/L** change category, **K** reads the selection and **P** requests directions. In **Navigation keyboard**, switch to **Brackets and backslash** to use **[ / ]** for destinations, **Shift+[ / Shift+]** for categories, **P** to read the selection and **Backslash** for directions. Each layout saves its own remaps and the selected layout persists. Both share the current category and destination. Activate a binding to change it, use Delete to unassign and Escape to cancel. A native binding takes precedence if the game claims the key later. An earlier settings remap that collides with the active navigation layout retains front-end access and uses F8 for recovery on the field.

On a controller, move the **right stick left/right** for destinations and **up/down** for categories. **Left trigger** requests directions. Press **View/Select**, release, then press the south button to read the selected destination or **Menu/Start** to open settings. F8 or its keyboard remap can also open settings in the field. The D-pad and left stick retain native movement. Controller support off restores native controls, with the existing recovery chord available on a settled field. The **Controller bindings** group supports remapping the field controls, including right-stick directions. **Unassign a controller binding** lists the optional bindings that can be cleared. A native controller remap that later occupies a direct field input takes precedence. Legacy settings retain valid mode and recovery bindings, so a preexisting trigger assignment can move the default directions input to the other free trigger or leave it unassigned if both are taken.

[The destination browser](../src/world/destinations.js) remembers one selection per nonempty category. It uses active native action, transfer, shop and battle pages with authored names or sprite roles for Objects, People, Merchants, Exits, Treasure and Enemies. Destination names and cardinal offsets describe the current selection. A new category without a prior selection starts at its nearest grid offset. Recognized treasure is labeled by type, and ordinary reward-granting pages use a generic interaction label. Spoken routes give up to eight legs in the form “1 north, 3 east, 4 north,” followed by the final facing or a notice that more directions are available. Accepted native cardinal movement advances one grid cell and calls the native step counter once. Direction speech uses that movement unit. The optional beacon follows the full verified course. Past the bounded warning-sign approach, cave directions offer a short timed preview or an optional one-tile cue. [Route beacon and controls](beacon.md) · [Timed cave directions](puzzles-and-secrets.md#timed-crossing-previews)

[The field owner](../src/world/field.js) accepts a command after native restoration, fade, movement, idle, save, terrain and display readiness, then rechecks on the rendered frame. [The snapshot](../src/world/snapshot.js) reads the active event positions and pages, the authoritative tile-event list, present boats and ships, and changed terrain cells from the already-restored tile table. Terrain moves as a compact transferable buffer. The renderer allows one worker request in flight, with one replacement request. Native movement, collision changes, flood entry, resize and transitions revoke the active request and any pending output. A result needs the same live owner, map and request identity. The development route makes no native movement or interaction call.

## Native movement and interactions

Walking follows stock `Game_Map.checkPassage`, `allTiles`, `isPassable` and `Game_CharacterBase.isMapPassable` in `package.nw/js/rmmz_objects.js`. Star layers yield to the next layer. The destination must also allow passage from the reverse direction. Active tile events precede the base layers in the native list order. Normal-priority events and present non-through boats and ships can occupy the destination.

`MapScene.js` `Game_CharacterBase.canPass` at original byte 107092 adds inclusive rectangular blockers. Their priority can differ from their collision state. The current event position and the rectangle offsets determine coverage. Erased and through events yield. The same custom plugin supplies `Game_Player.startMapEvent`, `canTriggerEvent` and `findEventsAt`, starting at byte 109478. The route endpoint tests native action priority and trigger, and supports the stock counter look-ahead only when the nearer tile has no startable event. Boat and ship movement use destination regions via `MapScene.js` `IsWater` at byte 11791. Region 253 is boat-only and 254 permits both. Boarding, disembarking and cross-map routing still need their own adapters.

`Tyruswoo_TileControl.js` `Scene_Map.onMapLoaded` at original byte 13959 applies the saved per-map table to the map data before calling native map setup. `setExactTileId` at byte 31297 writes the flattened layer index to that table and updates the live map when editing locally. Autotiling can write neighboring cells through the same setter. The source-checked local write at byte 31935 retires a pending route. `MapScene.js` `TileEditor.FloodFillRegion` at byte 32381 writes successive regions through that setter and yields between rings. The checked generator markers keep the field closed from native scheduling through generator completion. An in-flight route also retires before event page replacement, character and vehicle collision changes, tileset changes and accepted movement. Patrol timing remains a separate producer.

The cave adapter recognizes the island's conditional entrance, the internal floor transfers and the chamber return in **Exits**. Active floor mechanisms and the chamber statue appear in **Objects**. The worker uses the same live collision and native-priority approach for all of them, including the adjacent touch approach to the return exit. Native entry prompts and event handback govern the cave progression. [Cave progression and chamber](puzzles-and-secrets.md#cave-progression-and-chamber)

### Gated exits and floor events

In **Exits**, the two house stairs read their ordinary floor until the matching native passage opens. They then read **Secret room stairs**. **Objects** lists the hidden passage buttons. Caffeine Caverns has a **Hidden cave entrance** with a first-visit touch approach and a subsequent action-button page. From inside, choose **Return to Caffeine Caverns**. The Cauldron lists current entrances and returns in **Exits** and active pull handles in **Objects**. French Fry Forest lists the gate switches in **Objects**. [Authored access states](puzzles-and-secrets.md#ordinary-progression-and-secret-reachability)

When directions say “Floor event one tile north,” the described route stops on the tile before the event. Native controls still let you approach it and continue through any dialogue or scene. Request directions again when control returns. A guard may turn you back. If you are already standing on the selected touch entrance and can leave and return safely, directions ask you to walk off the tile and back. The beacon follows complete routes to the selected interaction.

[The local labels](../src/world/local-destinations.js) use the settled map and active event pages. The stair labels validate the two stock condition/transfer branches and read the corresponding live switch. The installed switch writes occur on the other side of the stairs or in the secret room, and the existing native map transition retires the old route. The registration verifier fingerprints the maps with these locators. Map 087 has a specific 1,463,068-byte read ceiling matching the installed file.

Stock `Game_Player.updateNonmoving` runs the on-tile touch check after a native step before continuing player input. The custom event check recognizes event rectangles and ignores the through flag for activation. `Game_Map.setupStartingMapEvent` accepts the first eligible starting event in map order. The worker builds a bounded tile table from the copied active non-normal touch events. It searches for a route clear of incidental events first. If only a geometrically walkable path exists, a second search traces its prefix to the tile before the first event. A selected touch entrance may still be the final tile. This uses the existing native markers and route worker. Moving actors, actions at a distance and special timed traversal have their own readiness and collision rules.

## Offline evidence and limits

The optional wall cues read the same live tile passage rules for lateral edges and observe the result of the player's native input attempt for bumps. A route result cannot create a bump. A patrol's native event takes precedence and revokes an active cue before locking the actor. [Controls and wall evidence](audio.md#wall-feedback)
