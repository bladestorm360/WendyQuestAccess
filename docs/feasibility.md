# WendyQuest accessibility mod feasibility

**Recommendation: use an RPG Maker MZ plugin for the game hooks.** The installed Windows game has a folder named `package.nw`. Its name looks like an archive, but the folder contains loose scripts, map JSON, PNGs and Ogg audio. The stock loader reads a plugin list and loads files from `js/plugins`. Offline, its installed functions accepted a synthetic last entry alongside the game's 23 enabled plugins. This makes a reversible plugin registration the first integration choice. It still needs a matched NW.js startup and safe scene readiness proof. See [engine evidence](engine-evidence.md) for the build, exact producer candidates and fixture limits.

The launcher and `nw.dll` statically import three `VERSION.dll` functions, so the proposed x64 DLL proxy has a plausible entry. Loading a DLL would still leave the harder problem: finding the correct NW.js renderer, JavaScript context and lifecycle, then getting to the same MZ functions the plugin loader already reaches. `WINMM.dll` has a broader contract, and `nw_elf.dll` is a shipped Chromium component used during startup. Use the proxy only if the reversible plugin route fails for a specific compatibility or installation reason and the proxy demonstrably solves it. See [Microsoft's DLL search order](https://learn.microsoft.com/en-us/windows/win32/dlls/dynamic-link-library-search-order), [NW.js packaging](https://docs.nwjs.io/For%20Users/Package%20and%20Distribute/) and [MZ's plugin documentation](https://rpgmakerofficial.com/product/MZ_help-en/01_05.html).

The game is short to play: Wendy's describes 5–10 hours. Development scope is larger. The build contains 239 maps and 6,527 event pages, including test/dev and map variants. The main costs are custom menus, battle timing and visual meters, routes that change with tile/event state, and optional secrets with dynamic obstacles. The public Steam listing describes single-player turn-based combat with timed attacks, five regions, and English interface/subtitles. The first target is the installed Windows x64 build; Steam Deck availability does not establish a native Linux port. macOS/Linux native builds and Windows under Proton are unverified; keep shared logic portable and verify only actual targets. [Steam listing](https://store.steampowered.com/app/3339970/WendyQuest_Legend_of_the_Four_Corner_Stones/) · [Publisher's gameplay estimate](https://www.wendys.com/index.php/blog/wendysr-square-deal-blog/rpg-mobile-game-real-food-rewards-wendyquest-just-dropped).

## Effort estimate

Remaining engineering hours for one developer and one supported Windows build, including implementation, offline verification, current feature documentation and local package/deployment checks. These are estimates from the inspected scope; the first checkpoint should narrow them before production code depends on any loader or input assumptions.

| Checkpoint | Hours | Deliverable that closes it |
| --- | ---: | --- |
| 1. Safe integration | 8–14 | Matched plugin startup/order, hashed install/uninstall contract, proven scene readiness gates, and a bounded speech handoff fixture. |
| 2. Shared controls and output | 14–22 | Effective keyboard/controller map, speech/review and settings framework, controller mode and handback, English catalog, Auto and persistent override. |
| 3. Menus, dialogue and quests | 18–30 | Title, save/load, custom menus, quest journal/HUD, cutscene dialogue, displayed values, review and details from actual producers. |
| 4. Battle and timing | 16–26 | Actual focus, targets, gauges, outcomes and phases; cues for native timed actions and their failure/success; turn order only if presented. |
| 5. World state and routes | 18–30 | Map audit, event eligibility and live collision overlays, world/boat transitions, useful labels, pathfinding, bookmarks and route cancellation. |
| 6. Puzzles and secrets | 20–34 | Verified Salt Caverns and secret cave traversal/feedback, hidden exits and optional-room reachability, ordinary unlocks and gated secret-ending access. |
| 7. Spatial audio and autowalk | 16–26 | Wall feedback, soundscape, beacon, HRTF and stereo/rear fallback, native movement with manual priority, independent settings. |
| 8. Combined verification and deployment | 12–22 | Cold/warm, busy and cancellation fixtures, cumulative timing review, exact package scans and hashes, recovery and local deployment, prioritized gameplay handoff. |
| **Total** | **122–204** | **About 3–5 full-time engineering weeks for the offline-verified Windows pass.** |

Reserve **8–24 engineering hours** after handoff for first gameplay findings, contingent on access to the affected progression. Player time and elapsed scheduling are separate. If the plugin is ruled out, budget an additional **16–32 hours to establish proxy feasibility and a safe renderer bridge** before committing to a replacement. That estimate buys a decision with evidence, not a guaranteed bootstrap. Re-estimate if timing variants, secret reachability or a second platform turns out to need a new integration. There is no reduced early gameplay handoff: these checkpoints are internal until every applicable baseline item is built and checked.

## Design and delivery

Install one original mod entry and owned payload. Make the installer validate the exact package/registry shape and selected producer fingerprints; append or remove only its own entry, leave unrelated plugins in order, use an atomic write and verify restoration. Steam updates or Verify Files can restore the registry. Give the player an accessible status and a safe reapply path that rechecks the new build before activation. Use isolated mod settings and logs outside `package.nw/save`. Preserve game saves, Steam Cloud, and native achievement and redemption behavior. Do not ship a game plugin list, alternate game runtime or copied game content.

The plugin owns narrow renderer-thread adapters. It copies bounded, presentation-ready text and small value/event updates; a separate worker or local service owns graph search, speech and HRTF audio. Use a qualified Windows screen reader backend (PRISM first to evaluate) and an audio owner with the approved SDL/HRTF dependencies. Prefer local asynchronous framed IPC if it can be qualified on this NW.js generation; a version-compatible Node-API module is a separate option. The shipped Greenworks addon proves native addons exist in the package; it does not prove a new addon ABI or that loading one on the renderer is safe. Worker, native pointer, event lifetime, IPC failure and process teardown must be explicit. No game wait for a helper, I/O, speaker or route. Use bounded queues and cancel obsolete generations. Do not suppress valid repeated text by content.

Derive walkability, target identity, route and audio eligibility from one map-state model. Bake base tile flags and connections offline, then reconcile active event pages, collision, switches and custom tiles/animated blockers. Do not copy entire maps or rescan every event on the game thread. Fail closed for unknown overrides. Pathfinding names may use developer data under the standing exception, with type-only treasure labels. Carry over the standard controller-only mod mode, two keyboard layouts, F8 if it passes conflict checks, independent sound/speech/HRTF controls, and default-off Autodetail, indexing, autowalk, autowalk path speech and partial step counts.

Salt Caverns is the first ordered-puzzle acceptance case. The optional secret cave is the key test of moving hazards, reset and accessible timing. Make directions and puzzle feedback useful with native controls; use nonverbal low-latency cues for fast windows rather than depending on speech timing. Report only clues and mechanics that the game has presented or that the user has already authorized. The mod should make secret content discoverable and playable, and normal travel should avoid unnecessary spoilers. See the [separate audit](puzzles-and-secrets.md).

Reuse ideas after verifying provenance and fit. [QuestersWhitestick](https://github.com/dengopaiv/QuestersWhitestick) is an existing MV/MZ screen reader package to evaluate for stock window behavior. Its own documentation notes that game updates can remove registry entries. WendyQuest's custom scene and puzzle requirements are independent of generic window coverage. Do not assume license permission, pin an unreviewed binary, or install it in this investigation.
