# Battle access

## Command focus

During a settled battle command menu, the mod speaks the focused command. It marks commands that the game displays as unavailable. The first command in a newly opened group also identifies the battle commands. A new native focus event can speak the same label again.

Press **I** to read the current command's visible description and cost. **Shift+Up** and **Shift+Down** review individual lines. **Shift+Left** and **Shift+Right** jump to the first or last line. On a default Xbox layout, press and release **View/Select**, then **A** to read details or use the D-pad for review. Mod mode accepts one review action and returns to ordinary battle input. The bindings can be changed in mod settings. **Autodetail** appends the visible details after focus and **Menu indexing** adds position and count. Both default off. [Shared menu controls](menus.md)

## Radial timing tones

In mod settings, open **Audio** and turn on **Battle timing cues**. This setting defaults off. Its volume starts at 65 percent and is independent of the sound, HRTF and speech switches. The Audio panel previews the lead, power, accuracy and ice-break tones. The lower lead tone precedes each tap tone. Confirm on the tap tone for the current stage. When the radial meter shows ice, use the two-note ice-break tone, then wait for the next lead and tap tones as the sweep resumes.

Build 26578620 uses radial action command ID 3 in the authored Wendy Basic Attack skill. The installed skill and equipment data audit found no authored ID 2 timing entry. `SkillUtility.GetSkillFromID` in `MonkeyWrenchMZ.js` reads the installed skill record. `ActionCommandRadial.BarParams` at byte 52045 of `ActionCommandCombat.js` supplies the actual ranges and speed. The power and accuracy markers at 71224 and 77631 run after the original geometry and input checks. They observe the current visible sweep, its critical segment, the frozen band while present, and the native pause or cutoff. A sweep with no highlighted segment uses its final usable approach. The runtime keeps the native result and input ownership.

The scheduler requests a lead tone around 190 ms before the predicted center and a tap tone around 34 ms before center. It accounts for the native half-speed zone when Frosty is active and uses the current displayed progression when the sweep wobbles. These offsets are the initial design choice for the installed build. Each visible window owns at most one lead and one tap request. Accepted input, ice pauses, the end of either sweep, a scene boundary and expired requests revoke pending audio. Spatial bearing follows the current target arc. The worker receives the cue identity, gain and bearing. The native objects stay on the renderer.
