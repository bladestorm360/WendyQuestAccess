# Battle access

## Command focus

During a settled battle command menu, the mod speaks the focused command. It marks commands that the game displays as unavailable. The first command in a newly opened group also identifies the battle commands. A new native focus event can speak the same label again.

Press **I** to read the current command's visible description and cost. **Shift+Up** and **Shift+Down** review individual lines. **Shift+Left** and **Shift+Right** jump to the first or last line. On a default Xbox layout, press and release **View/Select**, then **A** to read details or use the D-pad for review. Mod mode accepts one review action and returns to ordinary battle input. The bindings can be changed in mod settings. **Autodetail** appends the visible details after focus and **Menu indexing** adds position and count. Both default off. [Shared menu controls](menus.md)

## Enemy target focus

When the native target marker appears, the mod reads the selected enemy or group. It uses the name after the native label appears. Before then, it identifies the enemy by its left-to-right position. Identical displayed names include the position even with indexing off. **I** reads the visible HP bar as full, empty or an approximate percentage. The same details and review controls work in controller mod mode. Settings open from settled battle commands. During target review, the controller mode offers the review actions so the native timing and input remain available.

In `BattleSceneArranger.js`, `targetEnemy` at byte 195123 uses living enemy sprites in horizontal or vertical cursor order. `Sprite_Enemy.updateSelected` at 178374 reads the native target set, handles the directional keys and updates the selection arrow and outline. `updateSelectionArrow` at 175973 controls the visible marker. The enemy name is assigned from the battler at 185262 and shown by the name sprite's alpha transition at 178085. The mod waits for a rendered selection and reads actual painted names from the corresponding attached sprites. It uses the game's horizontal order for position. The authored troop data has at most five enemies, and the adapter bounds sprite inspection to eight.

In `ActionCommandCombat.js`, `ChangeActionTarget` at 9667 sets the native index, rebuilds the target list and gives it to the current command. The same battler can occur more than once in the native list. The mod reports each selected sprite once. It reads the visual HP fill using `Sprite_EnemyGauge.drawGaugeRect` at byte 187083 of `BattleSceneArranger.js` and the stock gauge's smoothed display rate. The inner bar is 62 pixels wide. The estimate is rounded to the nearest five percent for partially filled bars. Exact battler HP and maximum HP stay outside this display.

The native scene update marker at 242214 follows the sprite updates. A changed target set or newly cancelable timed action can schedule one postrender check. An unsettled selection has up to eight presented-frame attempts. Stable focus leaves the native marker with identity checks. Battle scene ownership, resize, fade, busy, modal, interpreter and overlay gates govern both presentation and manual review. The mod cancels the pending target and speech epoch before native cancellation at `ActionCommandCombat.js` byte 25684, radial windup at 67814, radial cleanup at 48198, and the original `BattleManager.startInput` and `startAction` bodies. Scene departure and interpreter setup also revoke admission. ### Target verification

The installed-method fixture used the real scene update, enemy selection and directional navigation, target update, gauge draw, cancellation and action start with a synthetic renderer. It verified initial and busy-scene withholding, visible selection, hidden names, duplicate enemy names, ordered multi-target review, the exact displayed gauge fill, native cancellation and no stale output at action acceptance. In two bounded runs the first target took 1.45–1.63 ms through the synthetic render and formatted receipt. The stable case ran 300 frames without another observer call. The matching NW.js fixture verified packaged target focus, indexed speech, Autodetail, controller detail and native confirmation handback. The speech and native audio build checks, the dialogue regression and all 16 registration candidates passed. The exact development payload scan and hashes were recorded before removing about 9.6 MB of generated staging.
