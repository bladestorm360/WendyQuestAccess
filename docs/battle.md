# Battle access

## Command focus

During a settled battle command menu, the mod speaks the focused command. It marks commands that the game displays as unavailable. The first command in a newly opened group also identifies the battle commands. A new native focus event can speak the same label again.

Press **I** to read the current command's visible description and cost. **Shift+Up** and **Shift+Down** review individual lines. **Shift+Left** and **Shift+Right** jump to the first or last line. On a default Xbox layout, press and release **View/Select**, then **A** to read details or use the D-pad for review. Mod mode accepts one review action and returns to ordinary battle input. The bindings can be changed in mod settings. **Autodetail** appends the visible details after focus and **Menu indexing** adds position and count. Both default off. [Shared menu controls](menus.md)

## Native producers and lifetime

The custom battle scene in Steam build 26578620 owns actor and option selection. `BattleManager.startInput` in `BattleSceneArranger.js` begins input at original byte 192424. The native command groups and their focus methods begin at 22843 and 23972. `createBattleOptions` at 140246 constructs the main actor's commands, and `AddSkillBattleOptions` at 143644 supplies the native skill names, descriptions and displayed costs. The installed class data has at most three authored skill learnings per class. The observer reads up to 16 entries in a current group.

`Sprite_BattleOption.update` at 161821 advances the sprite and checks whether it is active and focused. The marker at 162176 runs at that point before native confirmation. The option must belong to the current actor's native group and the scene's live UI layer. Availability follows the same prerequisite and lock flags as native acceptance. The observer tracks a change in those flags for the current focus. A disabled option keeps its native failure feedback.

`Sprite_Text` in `MonkeyWrenchMZ.js` separates text assignment at 115151 from bitmap repaint at 115403 and consumes the dirty flag during update at 120172. The observer waits for postrender and accepts only visible, attached, ready text with a cleared dirty flag. Names, descriptions and costs come from the rendered sprites. The shared review buffer keeps up to eight logical lines and preserves native order. The renderer owns the scene and option references. The speech transport receives bounded strings and metadata.

The battle readiness gate reuses the native busy result and checks the settled scene, input phase, modal and interpreter state. The pending observation is replaceable and uses one postrender callback per renderer. Native focus loss retires that option at 156577. Native acceptance closes it at 155370 before the action handler. Native battle update at `rmmz_managers.js` byte 62230 closes command work before a non-input phase runs. Interpreter setup at `rmmz_objects.js` byte 255063 retires it before loading event resources. Scene change, resize, blur and settings opening retire the context and its speech epoch. [Observer](../src/battle/focus.js) · [Registration](../tools/registration.py)

## Verification and remaining work

The bounded installed-method fixture exercised actual option focus, text update, acceptance and phase retirement with a synthetic bitmap and renderer. It verified dirty-text withholding, rapid focus replacement, an availability change, native disabled feedback, and cancellation before an accepted action. In one throttled comparison, 600 stable synthetic frames took 4.08 ms with the original method and 1.55 ms with the observer enabled. The first focus took 1.03 ms through a synthetic render and formatted receipt. The game still needs a comparable runtime measurement. The isolated matching NW.js 0.48.4 fixture checked packaged focus, keyboard details, controller review, return to native input, Autodetail and indexing.
